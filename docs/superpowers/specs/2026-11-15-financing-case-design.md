# Сквозной пример для заявки: проект дизайна

Статус: утверждён пользователем 15 ноября 2026 года; выполнение в текущем чате, публичный репозиторий Egorich51/project-finance-ai-case.

## Цель

За три часа подготовить дополнительный материал по одной ссылке: воспроизводимый разбор синтетического проекта от документов до предварительного расчётного заключения. Читатель должен увидеть источники значений, обнаруженные проблемы и связь результата с расчётами.

## Подходы

1. Схема архитектуры: быстро, но преимущественно повторяет заявку.
2. Исследование извлечения: показывает качество AI, но не связывает его с финансовым результатом.
3. Сквозной пример с небольшим исследованием: связывает документы, извлечение и расчёт; проверяет только один сценарий. Это рекомендованный вариант и рабочая основа плана после запроса пользователя на writing-plans; окончательное подтверждение ещё требуется.

## Предлагаемый объём

Один вымышленный проект приобретения оборудования. Исходники DOCX и XLSX, размеченный эталон, сохранённый фактический ответ AI, проверенные входные данные, Python-расчёт, Excel с формулами и Markdown-заключение. README служит главной страницей материала; GitHub-репозиторий — предлагаемое место публикации.

В документах намеренно присутствуют противоречие по бюджету и отсутствие собственного участия. До подтверждения человеком расчёт блокируется. После уточнения: бюджет 100 млн рублей, собственное участие 40 млн, потребность 60 млн, ставка 15% годовых, срок 5 лет, равные ежегодные платежи основного долга. CFADS по годам: [24, 26, 28, 30, 32] млн рублей. Стресс: снижение CFADS на 20%. Условный порог DSCR: 1.2. Все параметры придуманы для демонстрации и не являются методикой банка.

Расчётный предел долга — наибольший долг, удовлетворяющий порогу DSCR во всех пяти годах в базовом и стрессовом сценариях при заданном графике. Сумма для рассмотрения — минимум потребности и этого предела; отдельно показывается дефицит финансирования. Это условный результат демонстрации, не кредитное решение.

## Границы и честность выводов

- Бюджет времени: 180 минут, включая 30 минут резерва на проверку и публикацию.
- Нет веб-сервиса, RAG, обучения моделей, реального скоринга, полной прогнозной отчётности и интеграций.
- Исследуется один синтетический случай, а не качество на реальных банковских данных.
- 30% экономии времени и 95% точности из заявки остаются целями будущей проверки.
- Время автоматического запуска не выдаётся за экономию времени специалиста.
- Ответ AI сохраняется до исправлений; эталон не передаётся модели. Исправления хранятся отдельно.
- При отсутствии доступного модельного API допустим ручной запуск промпта с сохранением ответа и указанием способа запуска. Если запуск невозможен, материал называется расчётным примером с протоколом будущего исследования, без результатов AI.
- Синтетические документы не содержат персональных или конфиденциальных сведений. Ключи API и локальные настройки не публикуются.

## Критерии готовности

README объясняет пример за несколько минут и ссылается на исходники, результаты и ограничения. Один запуск воспроизводит расчёт и отчёт без доступа к модели. Источники каждого поля проверяются; пропуски и противоречия блокируют расчёт. Excel и отчёт содержат одинаковые суммы. Ссылка проверена без авторизации, если репозиторий опубликован публично.

## Решения, предложенные исполнителем

Python 3.11+, стандартный unittest, openpyxl и python-docx; простой локальный скрипт вместо интерфейса. Денежная единица расчёта — млн рублей. Публикация возможна после проверки имеющегося GitHub-доступа; отсутствие доступа не мешает собрать локальный комплект. Инициализацию Git выполнять при реализации, поскольку текущая папка пока не является репозиторием.
