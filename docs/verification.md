# Проверка и принятые решения

Это архив проверки первого этапа с одним проектом. Актуальная проверка двух бизнес-сценариев и GPU-сравнения находится в [benchmark-verification.md](benchmark-verification.md).

Проверка выполнена 15 ноября 2026 года. Материал относится к одному синтетическому пятилетнему проекту.

## Подтверждённые результаты

- 26 локальных тестов прошли, включая настоящий пересчёт Excel в LibreOffice. Проверены базовый случай, нулевая ставка, отсутствие долга, удалённое собственное участие, некорректный срок и отрицательная ставка.
- 75 числовых ячеек пересчитанного Excel сверены с Python с допуском 0.000001 млн ₽; ошибок Excel в опубликованном примере нет.
- DOCX и все четыре листа Excel отрендерены и просмотрены.
- Сохранённые сырой ответ, разобранный JSON и метрики совпадают; полный запрос соответствует только промпту и исходным документам. Повторное обращение к модели для проверки не требуется.
- Первая проверка GitHub Actions прошла на Python 3.11: установка зависимостей, тесты и создание расчётного комплекта. Проверка LibreOffice запускается отдельно локально; в CI этот необязательный тест пропускается.
- README, исследование, заключение и три Office-файла проверены без авторизации по публичным адресам и совпадают с локальными файлами.

Независимый ревьюер проверил код и повторил 25 тестов до заключительного исправления. Существенное замечание — падение оценщика при массиве или объекте вместо единицы измерения — воспроизведено отдельным тестом, исправлено и проверено полным набором из 26 тестов. Повторное независимое ревью после этого исправления не проводилось.

## Решения при выполнении

1. Создан отдельный вложенный репозиторий на ветке build-case: исходная папка не являлась Git-репозиторием. Исходные пользовательские материалы заявки в публикацию не включены; переносить существующие ветки не потребовалось.
2. Исправлены ошибочные контрольные суммы в первоначальном плане: базовый предел 57.142857, стрессовый 45.714286, дефицит 14.285714 млн ₽. Они следуют формуле и проверены независимо; неверный выбор здесь изменил бы финансовый вывод.
3. Использованы Python, openpyxl и python-docx. Для вычисления кешированных значений Excel нужен табличный движок: готовый файл пересчитан, а сгенерированный заново файл пересчитывается при открытии.
4. Для фактического эксперимента загружена локальная qwen2.5:1.5b, около 1 ГБ. Результаты ограничены этой небольшой моделью и одним сценарием, а не всеми LLM.
5. Банковская применимость, скоринг и полная отчётность оставлены за пределами демонстрации. Для практического применения нужны методика банка и проверка специалистами.
6. Не делаются выводы об общей точности модели и экономии рабочего времени. Бизнес-эффект остаётся непроверенной гипотезой.
7. Парсер рассчитан на фиксированный комплект исходников. Другие шаблоны и таблицы внутри DOCX потребуют адаптации.
8. Отдельная обработка численных переполнений при экстремальных значениях не добавлялась. Такой ввод может привести к ошибке; это не проверка производственной устойчивости.
9. Модель не запускалась повторно ради ревью: сохранён первый ответ без отбора успешной попытки. Публичные ссылки проверены исполнителем независимо. Новый запуск в другом окружении может отличаться.

## Отложенное небольшое замечание

При увеличении срока сверх пяти лет экспорт может подписать дополнительный CFADS адресом исходной ячейки, которая фактически пуста. На опубликованный пятилетний пример это не влияет. Перед исследованием более длинных проектов необходимо исправить подписи дополнительных лет и разметить новые источники; автоматически сгенерированные ссылки для этих лет нельзя считать подтверждёнными.
