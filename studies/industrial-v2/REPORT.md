## Финансовая проверка

Для каждого проекта построены 60 месяцев нового кредита, проценты, погашение, CFADS, денежный остаток и годовые DSCR. В Excel восемь листов с формулами, историей РСБУ и сценариями. Excel пересчитан LibreOffice: 3 492 числовые ячейки сопоставлены с независимым Python-расчётом; ошибок формул не обнаружено.

Операционные прогнозы, налоги, изменение оборотного капитала и бездолговой поток взяты из предоставленного JSON. Независимо проверена арифметика кредита, CFADS, ликвидности, NPV и IRR по этим предпосылкам; реалистичность продаж и затрат не подтверждалась. Коммерческие сценарии автора на листе «Сценарии» перенесены с явной пометкой, их операционная модель не перестроена.

- **Гофроупаковка:** базовый DSCR 1,188 ниже выбранного демонстрационного ориентира 1,20; NPV отрицательна.
- **Металлообработка:** положительная NPV и запас DSCR. Долг обслуживается потоком всего модернизируемого участка, а NPV рассчитана на приростном потоке относительно варианта без модернизации — эти периметры различаются.
- **Сушка:** первый год имеет отрицательный CFADS и DSCR, хотя месячный денежный остаток положителен благодаря финансированию. Минимум DSCR 1,454 относится только к годам погашения основного долга; NPV отрицательна.

Условные кредитные пределы предполагают неизменный CFADS и профиль выборки при масштабировании долга; налоговый щит не пересчитывается. Снижение кредита требует дополнительного собственного участия. Механический стресс: минус 20% абсолютного месячного EBITDA при фиксированных остальных потоках. Порог 1,20 выбран для демонстрации, не заявляется нормативом банка. Действующий долг компаний не включён в график нового проекта и раскрыт отдельно в заключениях.

### Ошибки и ограничения

У 7B 30 прогнозных полей отсутствуют: для гофроупаковки и сушки модель вернула только семь исторических показателей вместо 22 требуемых. Ещё два поля — нулевой долг металлообработки — ошибочно возвращены как null. Шесть правильных значений имеют неверные номера строк источника. Все эти ошибки остались в основном результате; повторного подбора промптов и замены ответов не было.

У 1.5B все шесть первых ответов не прошли прямой JSON-разбор. Ноль засчитанных полей означает непригодность ответа для этого строгого интерфейса, а не доказательство, что модель не прочла ни одного числа. Исправление синтаксиса вручную в основной метрике запрещено.

Все целевые значения в источниках присутствуют, ожидаемые issues пусты. Поэтому отсутствие ложных issues не доказывает умение находить пропуски или конфликты: полнота такого обнаружения здесь не проверялась. Три проекта не дают статистически надёжной общей точности, оценки экономии времени сотрудников или оснований автоматически одобрять кредит. Старый опыт 64/66 относится к другому набору и промптам и не сопоставляется с 82/114.

## Вход, эталоны и воспроизводимость

Одинаковые шесть задач на модель: условия финансирования (16 полей) и история 2025 года с прогнозом 2027–2031 (22 поля), итого 114 полей. Модели получили только размеченные выдержки Markdown и числовые кэшированные ячейки РСБУ XLSX. PDF сохранены как оригинальные дубликаты бизнес-планов; OCR и чтение PDF моделью не тестировались. JSON автора служит локальным источником финансовой модели и сверки эталонов, на GPU не передавался.

Каждое поле проверяется по значению, единице и периоду. Деньги нормализуются в млн ₽; для округлённых строк MD допуск 0,005001 млн ₽ или единиц коэффициента, для исторических ячеек — 0,000001 млн ₽. Источник засчитывается при точном совпадении хотя бы одного заранее разрешённого адреса. Пропущенные поля считаются ошибками. Сами [промпты](gpu-inputs.json), [эталоны](reference.json) и исходники заморожены коммитом `fda1186` до инференса; [манифест эксперимента](experiment.json) и [хеши исходников](source-manifest.json) проверяются при повторной оценке.

Две Tesla T4, по одной на модель. Qwen2.5-1.5B-Instruct и Qwen2.5-7B-Instruct: 4-bit NF4 с double quantization, FP16, greedy, seed 42, максимум 3000 новых токенов, суммарный бюджет 12288 без обрезки входа. Обучения не было. Точные ревизии, версии библиотек, токены, время, память, хеши промптов и неизменённый raw_text находятся в [сырых записях](results/raw/). Первоначальная попытка запуска до успешной загрузки файлов завершилась до инференса; после загрузки сохранены все 12 первых ответов.

```bash
python -m pip install -r requirements.txt
python scripts/summarize_industrial_study.py
python scripts/build_industrial_outputs.py
python -m unittest discover -s tests -v
python scripts/verify_industrial_excel.py --soffice /path/to/soffice
```

Первая команда оценки не требует GPU или сети. Пересоздание Excel возвращает формулы без вычисленных кэшей; откройте их в Excel/LibreOffice или выполните скрипт проверки. Готовые опубликованные Excel уже пересчитаны. Для нового GPU-запуска используйте `scripts/run_gpu_benchmark.py` с этим `gpu-inputs.json`, отдельной папкой результатов и флагами `--max-new-tokens 3000 --context-tokens 12288`; исходные ответы не перезаписывать.

Финансовые файлы построены по проверенному структурированному вводу, а не по неполному выводу LLM. Заключения сформированы детерминированно из расчёта. Связка демонстрирует извлечение → проверку → расчёт с участием аналитика; автоматическое сквозное кредитное решение не реализовано.
